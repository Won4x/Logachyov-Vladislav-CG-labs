SLIDE 5
Forward Rendering Делаем все, что нам нужно, чтобы затенить пиксель за один проход каждый меш передается по конвейеру, по одному за раз, для получения окончательного изображения каждый  меш   должен учитывать  каждый  источник света в сцене для каждого источника света   тени  (sampling shadow maps)  затухание на расстоянии   расчёт освещения и накопление дорогостоящие расчеты освещения должны быть выполнены для каждого видимого пикселя каждого полигона на экране сложность напрямую связана с количеством мешей и количеством источников света затенять маленькие треугольники неэффективно Состоит из двух этапов : Непрозрачный этап Прозрачный этап 5 При каком условии мы получим худший результат?

SLIDE 6
Forward Rendering Подходы к прямому рендерингу Повторный рендеринг геометрии для каждого источника света  ->  много прогонов геометрии  ( все еще вариант на старом оборудовании ) Пиксельный шейдер с четырьмя или восемью источниками света Хранение свойств источников света в текстурах и индексирование по этой текстуре  ->  Большое число чтений из текстуры и источники света не полностью динамически Некоторые графические движки считают освещение с ближайшими двумя или тремя источниками света в пиксельном шейдере, а  освещение на трёх или четырёх следующих источниках света в вершинном шейдере 6

Light Stage Запись в буфер глубины отключена Для каждого источника света   Отрисовка геометрического представления источника света Использование растеризации для отбраковки источников света и определения какие пиксели будут освещены Считывание входных данных для освещения из  G-buffer  Расчёт освещения   Накапливание освещения с помощью аддитивного смешивания 11

SLIDE 12
Transparent Stage Все прозрачные объекты визуализируются в стиле прямого рендеринга Все прозрачные объекты отсортированы от заднего плана к переднему и отрисованы в этом порядке Запись в буфер глубины отключена Источники света обрабатываются так же, как и при прямом рендеринге 12

SLIDE 13
Light Accumulation Мы не можем добавлять  ambient  часть модели  Фонга  для каждого источника света Добавьте отдельный  ambient  источник освещения Только направленный свет может добавлять  ambient  часть Каждый источник света вносит свою роль в общую яркость сцены Мы не можем просто перезаписать цвет в бэк-буфере Таким образом, нам нужно  складывать  яркость в бэк-буфер с помощью  BlendState 13

SLIDE 14
Deferred Rendering Pros and Cons Плюсы : Только один проход геометрии для главного вида  ( наверное больше десятка для других видов вроде теней, отражений, прозрачных объектов и так далее ) Источники света независимы от геометрии и поэтому ограничены только пропускной способностью памяти Минусы : Пропускная способность памяти  ( чтение из четырех текстур для каждого источника света ) Полный пересчёт уравнения освещения для каждого источника света Ограниченное представление материала в  G-Buffer Рендеринг прозрачных объектов отдельным проходом с прямым рендерингом Реализация MSAA сложнее по сравнению с  Forward   Renderer 14
